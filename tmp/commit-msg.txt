feat: 额度熔断（在额度用完之前切走）+ 按模型分账

冷却（health.mjs）是事后的：收到 429/402 才知道渠道不行了。对免费额度只是浪费一次请求，
但按量付费渠道的欠费发生在响应返回之前 —— 事后切换救不回来。所以补一层"事前"判断。

新增 lib/budget.mjs
- 软阈值（默认 90%）只把渠道排到候选队尾：别人能用就先用别人，剩余额度不浪费
- 硬阈值（默认 100%）彻底停用，且 pool 在"全在冷却就兜底"之前就把它剔掉
  （否则 force-any 会把已经打满的渠道捞回来再打一次，那正是本功能要防的事）
- 三层信息源：平台自报（响应头 x-ratelimit-remaining-tokens / 官方余额接口）
  > 本地累计（limits.tokens ÷ 本代理记录的用量）> 都没有就不干预、不猜
- 用量写 ~/.dsh/llm-router/usage.json，跨重启保留（否则重启一次等于额度回满）
- limits.perModel：同一渠道下多模型各自记额度（火山方舟那类"一把 key 下几十个模型"），
  一个烧完自动换下一个；policy.perModelCandidates 控制一次请求最多试几个模型

调度
- 429 / 404 只冷掉出问题的那个模型，同渠道别的模型照用（模型级冷却）；
  5xx / 网络 / 401 / 403 仍然冷却整个渠道
- 没配额度数字的渠道行为完全不变（只有 note 的老配置零影响）

面板
- 新增「额度」列、「额度用尽 / 额度降级」计数、「重置额度用量」按钮
- perModel 渠道显示「可用模型数 / 总模型数」，并列出烧完/降级的模型

端点
- GET /admin/budget-reset[?id=]（也走面板的 action 通道）
- POST /admin/report-balance（把平台自报的真实余额灌进账本）

其他
- cli.mjs 启动时打印哪些渠道启用了熔断、阈值是多少
- default-config.json：百炼填 100 万 token / 90 天，OpenRouter 开 balance:true
- 自测 27 → 64 项：软阈值降级 / 硬阈值剔除且兜底不捞回 / 上游响应头优先 /
  跨重启保留 / balance 零配置模式 / 多模型自动切换 / 429 只冷单个模型
